# 📬 MailRules Automation

Веб-интерфейс для управления правилами фильтрации почты на MailCow — работает как «Создать правило» в Outlook, только правила живут на сервере и не слетают при смене сотрудника или устройства.

## 🎯 Задача

У компании был свой почтовый сервер на MailCow (~2000 писем в день), но встроенная фильтрация требовала ручного редактирования Sieve-скриптов. Нужен был удобный интерфейс уровня Outlook, но с хранением правил на сервере, а не в почтовом клиенте.

## ⚙️ Как это работает

```
Браузер → FastAPI → IMAP (читает письма)
                 → SQLite (хранит правила)
                 → ManageSieve → Dovecot (применяет правила на сервере)
```

1. Пользователь открывает письмо → нажимает «Создать правило»
2. Форма автоматически подставляет отправителя, домен, тему письма
3. При сохранении правило конвертируется в Sieve-скрипт и загружается на сервер через ManageSieve
4. Все входящие письма автоматически раскладываются по папкам — независимо от того, с какого устройства или клиента работает пользователь
5. Есть опция применить правило ретроактивно — к уже существующим письмам, не только новым

## 🧩 Нетривиальные технические задачи

- **Кириллица в названиях папок** — протокол IMAP требует модифицированную кодировку UTF-7 для не-ASCII символов. Пришлось писать свои функции кодирования/декодирования (пример — в `snippets/imap_utf7.py`)
- **Дедупликация правил** — правила подтягивались из двух источников (пользовательский интерфейс и существующие Sieve-скрипты SOGo), нужно было избежать дублей при импорте
- **Синхронизация состояния** — при любом изменении правила через API бэкенд пересобирает весь Sieve-скрипт заново и загружает на сервер, чтобы порядок приоритетов и логика совпадали

## 🛠 Стек технологий

- **Backend:** Python, FastAPI, SQLite
- **Протоколы:** IMAP (чтение почты), ManageSieve (управление фильтрацией на сервере Dovecot)
- **Аутентификация:** JWT
- **Деплой:** Docker, Docker Compose

## 📂 Структура проекта

```

│   ├── database.py    # Инициализация SQLite

├── frontend/
│   └── index.html     # Интерфейс пользователя
├── docker-compose.yml
└── Dockerfile
```
